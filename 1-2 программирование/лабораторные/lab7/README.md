# Лабораторная работа №7

## Вариант 3444344

## Задание

Доработать программу из лабораторной работы №6. Организовать хранение коллекции в реляционной СУБД PostgreSQL, добавить регистрацию и авторизацию пользователей, разграничить права на изменение объектов и реализовать многопоточную обработку запросов.

## Требования

Необходимо выполнить следующие требования:

- хранение коллекции должно быть организовано в PostgreSQL;
- хранение коллекции в файле необходимо убрать;
- для подключения к кафедральной базе данных использовать host `pg`, database `studs`;
- для генерации поля `id` использовать средства базы данных, например sequence;
- при запуске сервера коллекция должна загружаться из PostgreSQL в память;
- все команды получения данных должны работать с коллекцией в памяти, а не обращаться к базе данных;
- состояние коллекции в памяти должно изменяться только после успешного изменения данных в базе данных;
- необходимо реализовать регистрацию и авторизацию пользователей;
- пароль пользователя должен храниться в базе данных в виде хэша MD2;
- команды неавторизованных пользователей должны отклоняться;
- для идентификации пользователя клиент должен отправлять логин и пароль с каждым запросом;
- при хранении объектов необходимо сохранять логин пользователя, который создал объект;
- пользователи могут просматривать все объекты коллекции;
- пользователи могут изменять и удалять только свои объекты;
- для многопоточного чтения запросов необходимо использовать `ForkJoinPool`;
- для многопоточной обработки полученного запроса необходимо создавать новый `Thread`;
- для многопоточной отправки ответа необходимо использовать fixed thread pool;
- для доступа к коллекции необходимо использовать потокобезопасную коллекцию из `java.util.concurrent`;
- обмен данными между клиентом и сервером должен осуществляться по протоколу TCP;
- объекты между клиентом и сервером должны передаваться в сериализованном виде.

## Обязанности серверного приложения

- подключение к PostgreSQL;
- создание необходимых таблиц и sequence;
- загрузка коллекции из базы данных в память при запуске;
- управление коллекцией объектов;
- выполнение команд клиента;
- регистрация и авторизация пользователей;
- проверка прав пользователя на изменение объектов;
- добавление, обновление и удаление объектов сначала в базе данных, а потом в памяти;
- назначение `id` объектам средствами базы данных;
- ожидание подключений и запросов от клиента;
- чтение запросов через `ForkJoinPool`;
- обработка команд в отдельных потоках;
- отправка ответов через fixed thread pool;
- логирование основных этапов работы сервера.

Серверное приложение должно состоять из следующих модулей, реализованных в виде одного или нескольких классов:

- модуль приёма подключений;
- модуль чтения запроса;
- модуль обработки полученных команд;
- модуль отправки ответов клиенту;
- модуль работы с базой данных;
- модуль работы с пользователями.

Серверная команда `save` больше не используется, так как коллекция хранится в PostgreSQL.

## Обязанности клиентского приложения

- выбор действия при запуске: регистрация или вход;
- чтение команд из консоли;
- валидация вводимых данных;
- сериализация введённой команды и её аргументов;
- отправка команды на сервер вместе с логином и паролем пользователя;
- обработка ответа от сервера, то есть вывод результата исполнения команды в консоль;
- выполнение команды `execute_script` на стороне клиента;
- завершение клиентского приложения по команде `exit`.

Команда `save` в клиентском приложении не используется.

Важно: команды и их аргументы должны представлять из себя объекты классов. Недопустим обмен простыми строками. Так, для команды `add` или её аналога необходимо сформировать объект, содержащий тип команды и объект, который должен храниться в коллекции.

## Дополнительное задание

Реализовать логирование различных этапов работы сервера: начало работы, подключение к базе данных, получение нового подключения, получение нового запроса, отправка ответа и т.п. Логирование необходимо выполнить с помощью Log4J2.
